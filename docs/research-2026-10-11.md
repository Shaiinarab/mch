## Defects found by the QA audit and fixed in v0.6.0

1. HIGH — install.sh reported `INSTALL OK` while managed writes silently failed
   (a `skills` file blocking the directory). Now `INSTALL FAIL` + exit 1.
2. test.sh `hashes()` was vacuous for paths with spaces (xargs word-split);
   now `find -exec cksum {} +`, plus a non-vacuity self-check.
3. `set -u` + unset `HOME` crashed install.sh without a summary line. Now a
   clean `INSTALL FAIL` line.
4. Empty/whitespace `HARNESS_VERSION` installed with `version=` blank. Now
   refused (`INSTALL FAIL`).
5. doctor ignored a conflicting root `SKILL.md` ("exactly one SKILL.md" was
   prose). Now warns; also warns on stale BOOTSTRAP.md.
6. `date`-unavailable fallback seeded `memory/unknown.md`, breaking the
   filename contract and cross-run idempotency. Now skips with a warn.
   (The BOOTSTRAP.md seed policy changed with it: starter-only, never
   resurrected after first run deletes it.)
7. Consistency: "Three routes" listed four; route B could not pass STEP 3
   verify (missing BOOTSTRAP/HARNESS_VERSION); route C lacked install.sh;
   BOOT report `merged` count had no emitter; `INSTALL FAIL` was undocumented.
   All aligned across README/PROMPT/install.sh/doctor.sh.

## Rejected (with reasons)

- Compaction/pruning tuning knobs, bootstrap budget numbers, context-engine
  plugin APIs — config territory; mch never edits `openclaw.json` (see
  openclaw-fit.md "not adopted").
- Standing-orders templates, path-scoped rules (`.claude/rules/`), registry
  signing mandates — product-scale or platform-specific features without an
  mch-sized use.
- "Advisory guardrails" full frameworks — one promoted rule (#9) covers the
  actionable core.

## Second wave (final pass, 2026-10-11)

The closing round added process rules from 2026 harness-engineering sources
(LangChain "Anatomy of an Agent Harness", Osmani "Agent Harness Engineering",

one-page DEPLOY.md publish checklist.

engines, unattended "dreaming" automation, MCP trust scanning — reasons in the
two raw reports.
